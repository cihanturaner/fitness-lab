## Missions

   and a brand-new typed exercise ("Use “Triceps Curl” for this workout"). Case/whitespace
   normalised; only that workout changes; History keeps "Performed: X · Planned: Y".

   keep their own rows, set count, completion evidence and history identity. No merging by
   `exercise_id`; "Sets are recorded under exercise N above" removed.
3. **Nutrition target UX** — the macro target is a persistent setting ("Current targets:
   150P · 300C · 60F / 2340 kcal · Edit targets"); the daily form is intake only; kcal is
   always derived; effective date defaults to today; effective-dated history kept; initial
   setup never asks for the weeks 1–2 exception; changing an established target still does.
4. **Settings › Program in Turkish** — every remaining English label and prose line in the
   rendered Program / Program Rules area; exercise names, RIR, P1/P2/P7′, formulas, numbers
   and source tokens verbatim.
5. **History** — the day timeline is the only primary view; Sessions removed; exercise
   history is a secondary link ("Exercise history →"), not a tab.

## Decisions

- D1 **Slot placement needs a schema change** (migration 0008, additive): without a stored
  fact of *which slot a set was recorded in*, two slots with the same performed exercise are
  indistinguishable — no read-time rule can split them. `performed_set_slot (set_id PK →
  performed_set CASCADE, workout_id, planned_workout_id, slot_id)` is an association table
  like `workout_slot_substitution`: `performed_set` and `workout` are not altered (M1 §17),
  and it links to a planned *slot* (an occurrence in the session), never to a `planned_set`
  (M2 invariant 8: no set → prescription link). Composite FKs make a cross-workout placement
  impossible; triggers refuse edits while complete and a placement whose set exercise is not
  the slot's exercise for that workout. Nothing is backfilled: sets recorded before 0008 are
  shown by the old rule (first slot with that exercise), so no recorded row is rewritten.
- D2 A slot's exercise change keeps its placed sets only when they are of the new exercise;
  the others become extra work of their own exercise (as V3.3 already said: "N saved sets
  stay recorded as X"). They are recorded as extra (`slot_id` NULL) — found in the blocking
  review: merely deleting their placement let the pre-0008 rule move them into *another* slot
  performed as their exercise, i.e. a merge. Extra work added on screen is recorded the same
  way (`slot_id: null`); an API call that omits `slot_id` records nothing (pre-0008 rule).
- D3 Free-text exercise: name = whitespace-collapsed, trimmed; an all-lowercase entry is
  title-cased ("triceps curl" → "Triceps Curl"), any other casing kept ("EZ-bar curl" stays).
  Match against existing identities is case- and whitespace-insensitive (name, no
  equipment); an existing active one is reused, a retired one is refused (never revived),
  else it is created — find, create and substitute in one transaction
  (`PUT /api/workouts/{id}/slots/{slot}/typed-exercise {name}`).
- D4 Weeks 1–2 exception applies only to an *established* target: one in force before today.
  A first target (none yet, or one set today / dated ahead and not yet in force before today)
  is setup and never asks. Unchanged: the rule stays client-side decision support.
- D5 History language stays English like the rest of the UI ("Exercise history →"); only
  Settings › Program is Turkish (as asked).

## Blocking review findings (all fixed, with regression tests)

1. Sets left by a changed slot could be re-placed by the pre-0008 rule into another slot of
   their exercise (a merge). Fixed: explicit extra placement (`slot_id` NULL).
2. Exercise history "vs previous" compared two slots of one session on the same day. Fixed:
   a series is session + slot.
3. Typed name matching a retired and an active identity spelled alike could pick the retired
   one and refuse. Fixed: the active identity wins.

## Risks / notes

- Sets recorded before 0008 in an A/B/A session stay under the first slot of their exercise
  (unchanged behaviour); new sets go to the slot they are entered in.
- Approved-substitute names such as "Another Leg Extension Machine" are source identifiers
  (exercise identities in the Change panel), so they stay verbatim in the Turkish rules.
- Exercise history counts sessions per workout; one workout with two slots of the exercise is
  one session and two rows.
- 0008 has not been rehearsed on a copy of the canonical database (it is not in this cloud
  checkout); the rehearsal test covers a V3.3 database with legacy sets and a substitution.
